# ITMO-Software-Design-Roguelike

## Roguelike

### 1. **Общие сведения о системе**

Roguelike — это 2D игра с консольным интерфейсом, где игрок управляет персонажем, исследующим случайно генерируемые подземелья. Основная задача — продвинуться как можно дальше, собирая полезные предметы, убивая монстров и прокачивая способности героя. Жанр выделяется высокой сложностью и перманентной смертью персонажа, что побуждает экспериментировать с разными стратегиями и подходами.

- **Жанр**: Roguelike с традиционной консольной графикой.
- **Цель**: Исследовать подземелья, находить предметы, улучшать персонажа и побеждать врагов.
- **Особенности**: Запуск в консольном режиме без графического интерфейса.
- **Платформа**: Кроссплатформенная (Windows, Linux, macOS).

### Запуск

Находясь в корне репозитория, выполните команду
```
go run .
```

### 2. **Architectural Drivers**

#### Технические ограничения:
Используются стандартные устройства ввода и вывода: клавиатура для управления и монитор для отображения информации.

#### Функциональные требования:
1) Персонаж игрока может перемещаться по карте с использованием клавиатуры.
2) Карта генерируется случайным образом.
3) У персонажа есть характеристики: здоровье и сила атаки.
4) Персонаж имеет инвентарь для хранения вещей, которые он носит с собой.
5) Вещи из инвентаря можно надевать и снимать, при этом надетые вещи изменяют характеристики персонажа.
6) Вещи изначально находятся на карте и могут быть подняты, чтобы добавить их в инвентарь.
7) Снятые вещи остаются в инвентаре и могут быть надеты снова в дальнейшем.
8) Игра использует консольную графику

### 3. **Роли и случаи использования**
**Роли:**
1. Игрок:
   - Управляет персонажем с помощью клавиатуры.
   - Взаимодействует с игровыми объектами и окружением.
   - Осуществляет управление инвентарем и экипировкой персонажа.

2. Разработчик/Дизайнер уровней:
   - Создает уникальные уровни и игровые сценарии.
   - Устанавливает параметры для генерации карт.
   - Добавляет новые игровые элементы: объекты, врагов и предметы.

**Случаи использования:**
1. Перемещение персонажа

   - Игрок управляет движением персонажа по карте с помощью клавиатуры.

2. Взаимодействие с айтемами

   - Игрок подбирает оружие и защитные предметы, такие как мечи и щиты.

3. Управление инвентарем

   - Игрок открывает инвентарь, изменяет экипировку, надевая и/или снимая предметы, а затем закрывает инвентарь.

4. Сражение с монстрами

   - Игрок атакует монстров, используя навыки и предметы для достижения победы.

5. Завершение игры

   - Если персонаж умирает, игра завершается поражением игрока.
   - Если игрок успешно проходит 5 уровней, игра завершается победой игрока.

### 4. **Описание типичного пользователя**

1. Возраст: 16–50 лет.
Этот возрастной диапазон охватывает как молодых игроков, ищущих вызовы, так и более опытных геймеров, которые ценят сложность и стратегическую глубину.

2. Опыт:
Игрок обладает средним или высоким уровнем игрового опыта. Он знаком с основными механиками жанра RPG и, скорее всего, играл в другие roguelike или схожие игры. Такие пользователи комфортно осваивают новые системы, даже если они сложны и не имеют явных обучающих элементов.

3. Интересы:
Любовь к стратегическому планированию и тактике.
Желание исследовать процедурно генерируемые миры и открывать неожиданные игровые ситуации.
Увлеченность играми, где важны принятие решений, управление ресурсами и развитие персонажа.
Уважение к минималистичному или ретро-стилю графики, таким как ASCII или пиксель-арт.

4. Мотивация:
Испытание своих навыков в сложных игровых условиях.
Преодоление трудностей, изучение новых стратегий и улучшение собственной игры.
Удовольствие от уникального игрового опыта, где каждый запуск игры отличается от предыдущего.
Исследование загадочных и таинственных миров с высокой степенью реиграбельности.

5. Психологический портрет:
Этот игрок не боится ошибок и учится на неудачах. Он ценит процесс самосовершенствования и способность адаптироваться к сложным условиям. Такой геймер ищет в играх не просто развлечение, а интеллектуальный вызов, который позволяет раскрыть его стратегическое мышление и творческую находчивость.

6. Технические предпочтения:
Готов играть в играх с минимальными требованиями к графике, где акцент сделан на игровую механику.
Предпочитает кроссплатформенные решения, чтобы иметь возможность играть на различных устройствах (ПК, ноутбуки).

### 5. **Композиция системы**

#### Диаграмма компонентов:
```
+--------------------+
|   User Interface   |
+--------------------+
           |
           v
+--------------------+
|    Input Handler   |
+--------------------+
           |
           v
+--------------------+        +--------------------+
|    Game Engine     |<------>| Inventory Manager  |
+--------------------+        +--------------------+
           |
           v
+--------------------+        +--------------------+
|   Level Generator  |<------>|    Item Database   |
+--------------------+        +--------------------+
           |
           v
+--------------------+
| Graphics Renderer  |
+--------------------+

```

**Описание компонентов:**
- **User Interface (UI)**: Отвечает за отображение текстовой графики на экране, включая карту, подсказки управления, инвентарь, здоровье и параметры игрока. Также отвечает за обработку пользовательского ввода, связанного с инвентарем (например, выбор и экипировка предметов), через взаимодействие с Input Handler.

- **Input Handler**: Обрабатывает ввод с клавиатуры, включая команды для перемещения, атаки, открытия/закрытия инвентаря, выбора и экипировки предметов. Передает команды в Game Engine.

- **Game Engine**: Основной модуль управления логикой игры. Обрабатывает состояния объектов, включая игрока, монстров, предметы и взаимодействия между ними. Управляет переходом между уровнями, определяет условия победы или поражения.

- **Inventory Manager**: Обеспечивает управление инвентарем: добавление предметов при их поднятии, надевание и снятие экипировки. Синхронизируется с игровым движком для применения модификаторов характеристик игрока.

- **Level Generator**: Создает случайно сгенерированные уровни, включая комнаты, коридоры, начальную позицию игрока, монстров и предметы. Предоставляет игровому движку карту уровня.

- **Item Database**: Хранит шаблоны предметов (например, броня, оружие) и их характеристики. Обеспечивает доступ к данным о предметах для модуля управления инвентарем и игрового движка.

- **Graphics Renderer**: Отвечает за визуализацию игрового мира в консольной графике. Обновляет отображение карты, позиции игрока, монстров, предметов и интерфейса.

**Описание основных классов:**
- **Game**: Основной класс, управляющий игровым процессом. Обеспечивает обновление игрового состояния, обработку ввода, переходы между уровнями и отрисовку. Хранит ссылку на текущего игрока (Player), карту (GameMap), а также статус игры (текущий уровень, GameOver и т.д.).

- **Player**: Представляет игрового персонажа с характеристиками (здоровье, атака) и действиями (движение, атака, управление инвентарем). Содержит методы для взаимодействия с предметами и монстрами.

- **GameMap**: Представляет текущий уровень игры, включая тайлы, монстров и предметы. Содержит методы генерации карты, размещения монстров и предметов.

- **Monster**: Представляет врагов на карте. Имеет разные типы поведения (агрессивное, пассивное, трусливое) и может атаковать игрока.

- **Item**: Представляет предметы в игре, такие как оружие и броня. Хранит модификаторы, влияющие на характеристики игрока.

### 7. **Взаимодействия и состояния**

#### Диаграмма последовательностей

**Сценарий: Игрок надевает предмет из инвентаря.**
```
Игрок               Game               Player                                Item
  |                   |                   |                                   |
  | ---нажимает i --- |                   |                                   |
  |------------------>|                   |                                   |
  |                   |----EquipItem()--->|                                   |
  |                   |                   |---Проверка типа------------------>|
  |                   |                   |                                   |
  |                   |                   |                                   |
  |                   |                   |---RecalculateStats()------------->|
  |                   |                   |                                   |
  |                   |                   |                                   |
  |                   |                   |<--Пересчитать характеристики------|
  |                   |<----Подтверждение-|                                   |
  |<--Обновление UI---|                   |                                   |
```

#### Диаграмма состояний

**Состояния персонажа:**

1. **Idle (Ожидание)**
Персонаж не совершает активных действий, ожидает ввода с клавиатуры.
Момент между нажатиями клавиш (W, A, S, D, I и т.д.).

2. **Moving (Движение)**
Персонаж перемещается по карте (походив на одну клетку вверх, вниз, влево или вправо).
Происходит при нажатии W/A/S/D и успешной проверке на проходимость клетки.

3. **Attacking (Атака)**
Персонаж атакует монстра, если пытается переместиться на клетку с монстром.
Вызывается Player.AttackMonster(monster), если в новой позиции обнаружен монстр.
После атаки персонаж и монстр получают урон.

4. **Interacting (Взаимодействие)**
Персонаж подбирает предмет с клетки.
При перемещении на клетку с предметом вызывается Player.PickUpItem(item).

5. **Managing Inventory (Управление инвентарем)**
Персонаж находится в меню инвентаря, где может экипировать или снять предметы.
Активируется при нажатии I (открыть/закрыть инвентарь) и обрабатывается в Game.HandleInventoryInput().

6. **Dead (Смерть)**
Персонаж погиб. Игра завершается (Game Over).
Если Player.Health <= 0, устанавливается флаг GameOver = true.


**Переходы между состояниями:**

- **Idle → Moving**
При нажатии W/A/S/D и наличии свободной клетки для перемещения.

- **Idle → Attacking**
При нажатии W/A/S/D, если следующая клетка занята монстром:

- **Idle → Interacting**
При нажатии W/A/S/D, если следующая клетка содержит предмет:

- **Idle → Managing Inventory**
При нажатии клавиши I, если инвентарь закрыт.

- **Managing Inventory → Idle**
При повторном нажатии I или Esc, если инвентарь открыт.

- **Любое состояние → Dead**
Если в результате атаки монстра, если после атаки Player.Health <= 0.
